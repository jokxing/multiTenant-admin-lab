# 项目介绍与技术导览

本文介绍 MultiTenant Admin Lab 的个人贡献、展示路线和核心代码，供项目评审与面试阅读。先运行页面，再选择一条链路深入查看，无需完整阅读所有源码。

简短问答见 [README：设计与面试讨论](../README.md#设计与面试讨论)，可先阅读设计取舍，再按本文入口查看实现。

## 项目背景与个人贡献

原项目是基于 SoybeanAdmin 二次开发的 SaaS 后台。本人从开始主导后台前端，负责技术选型、前端工程结构、需求拆解、接口协商、复杂功能与公共组件封装，并负责后台代码评审。

最初两名前端分别承担后台和移动端，有时间时互相支援。随着后台规模扩大，增加一名前端承担较简单的页面设计配置、菜单规则及接口对接；复杂功能由本人指导实现，或封装组件供其复用。代码评审重点是规范和逻辑清晰度。

本人负责的实际工作包括配置驱动列表与表单、拖拽及多种排序动作、语言组、上传选择组、动态选择与搜索、币种联动等复杂交互，以及首页和活动的后台编排。移动端由另一名前端主要负责，本人还支援首页、客服的页面和功能，并与其约定首页组件字段；大部分移动端 UI 组件及主要接口联调由该同事与后端完成，不将移动端全部实现计为个人独立贡献。

原项目早期以手写代码为主，使用 VS Code 的 AI 补全，后期使用 Cursor 辅助。当前作品使用 AI 辅助提炼和实现，由本人结合原项目经验确认范围、检查交互并整理说明。

| 能力 | 原项目经验 | 当前作品 |
| --- | --- | --- |
| 配置驱动列表与表单 | 本人负责，通用配置配合复杂组件 | 提炼配置驱动思想，使用较小的 Schema 和演示场景 |
| 公共排序列 | 本人负责拖拽、置顶、上下移及通用页面动作传递 | 内容推荐列表；统一入口、本地保存、失败回滚；仅完整列表内排序 |
| 复杂表单 | 本人负责语言组及动态、联动组件 | 多语言素材组作为代表案例，不声称迁移全部原组件 |
| 配置发布与回滚 | 原项目没有 | 展示阶段新增，使用本地快照和版本记录 |
| 菜单与按钮权限 | 后端根据角色和菜单规则返回，前端据此展示 | 本地角色配置与权限点联动，不是生产授权系统 |
| 实时通道 | 原项目采用 WebSocket | 本地事件、消费队列和连接状态演示 |

选择代表案例而非完整迁移，是为了在独立工程中清晰展示可复用的前端设计，避免依赖原业务、接口和数据。版本发布、失败注入等展示机制不作为原项目历史上线成果。

## 演示路线

### 配置与运行时：约两分钟

1. 进入“页面配置器”，选择已有页面，修改列或操作按钮。
2. 对照 JSON 与可视化配置，观察预览和草稿差异，发布后打开“预览页面”。
3. 在“版本记录”中查看快照和回滚；回滚会形成新的发布记录。

重点观察配置、组件和运行时的分工，而非只看静态页面。

### 复杂排序：约两分钟

1. 选择“内容推荐列表”，确认有 `sortable` 列，进入其已发布运行时。
2. 演示拖拽、置顶及上下移，刷新确认顺序回填。
3. 开启“下次保存失败”，再次排序，观察错误反馈和原顺序恢复。
4. 输入筛选条件，观察排序禁用；清空后恢复。

默认模板路径为 `/demo/runtime/content-recommend`。按模板新建时使用自己填写的标识和路由，建议通过“预览页面”进入。

### 多语言素材组：约两分钟

1. 选择“多语言素材组表单”，进入表单预览或已发布运行时。
2. 填写简体标题和素材，切到英文再切回，确认输入保留。
3. 英文仅填写说明并提交，观察切到出错语言及标题校验。
4. 完整填写后保存、刷新回填；开启失败开关验证输入保留。
5. 在表单 JSON 中写入未知类型，应用时拒绝，原配置及预览输入保留。

默认模板路径为 `/demo/runtime/lang-asset-form`。素材选择说明显示在卡片下方。

### 按兴趣选择补充演示

- 角色权限：发布一个配置按钮后，到“角色权限配置”刷新权限点，调整角色并发布，对照运行时角色视图。
- 实时待办：发送重复和突发事件，观察接收、消费、重复计数及队列；断线按钮演示连接状态恢复。
- 首页与活动编排：启动独立移动端工程后查看 iframe，联调要求见[双端说明](admin-mobile-integration.md)。

JSON 是运行时输入，不能只依赖 TypeScript。表单应用前校验字段标识、类型、语言配置及规则等结构，拒绝非法配置再保留有效状态；这不是任意脚本执行器，也不能将局部校验器称为完整通用 JSON Schema 标准实现。

### 代表案例一：配置生成列表的复杂排序

原后台的列表由配置生成，排序列同时提供拖拽、置顶、上移、下移。本人将行、列标识和动作传给通用页面，再结合列表上下文组织参数并对接后端。难点是复用统一交互入口，而非在每个页面单独写按钮。

当前案例通过 `sortable` 列启用排序，组件把动作交给 `dispatchSortAction`，由纯函数按实体 ID 生成顺序，再交给 Mock 保存。提交期间禁用操作；失败恢复之前的顺序。拖拽在表格 DOM 就绪后绑定，卸载时销毁。

拖拽依赖 DataTable 实际 tbody：当前实现关闭立即初始化，待 nextTick 后查找目标，目标变化先销毁旧实例，页面退出后不再启动。首版过早绑定曾中断组件更新并影响弹窗关闭；因此类型检查和构建不能代替 DOM 生命周期的浏览器验证。这是当前展示阶段排障，不作为原工作历史故障描述。

### 代表案例二：配置与复杂表单组件组合

通用配置表达字段结构、布局和规则；语言组内的输入、切换、素材选择与错误定位交给专用组件。这样保留配置能力，也避免在 Schema 中堆积复杂交互。

组件通过克隆值和事件更新模型；错误按“字段 + 语言 + 子字段”定位。草稿以页面和字段隔离，同一页多个素材组一次保存；提交时取快照，失败不清空输入，切换页面后不把旧结果回填到新页面。

当前保存是一次 localStorage 表单写入，不是服务端多实体事务；页面 scope 检查保护切页后的状态，但不代表跨标签并发冲突已解决。旧单素材组保存接口仍存在，演示以当前表单接口为入口，不建议手工混用两种存储结构。

### 配置与权限联动

原项目的角色和菜单权限由后端提供，本人负责前端接口协商、规则配置及展示。当前作品从已发布配置提取页面和按钮权限点，转换为角色记录，再用共享判断过滤运行时操作。

入口：[角色权限页](../src/views/demo/permission/index.vue)、[角色模型与判断](../src/views/demo/shared.ts)、[权限实验台](../src/views/demo/capability/index.vue)。

页面与按钮权限需要一致，但隐藏按钮不等于接口授权。策略及演示审计在内存中，不提供服务端持久化；真正的租户隔离须在后端落实。

### 双端客服会话台

入口：[服务台页面](../src/views/demo/service-desk/index.vue)、[客服 API](../src/service/api/support.ts)。后台从 VITE_MOBILE_RUNTIME_URL 提取 origin（默认 localhost:4180），通过 HTTP 与 EventSource 访问移动端 Nuxt 的 /api/support 服务。

两端共用该 Nuxt 进程内的 Mock 会话，不是各自独立的客服存储，也不是后台“实时待办”页的本地消息队列。后台可接入 waiting 会话、快捷回复、标记 agent 已读及结束会话；移动端发送 customer 消息、标记 customer 已读。SSE 通知触发 HTTP 刷新列表和详情，数据在服务重启后不保证保留。

建议先启动移动端服务，再启动后台，打开“客户服务会话台”和移动端同一会话，演示客户发送→后台接入回复→移动端读取→后台结束后只读。这是源码支持的体验路线，本轮未重新运行双端浏览器验收，不据此声明完整客服闭环已测通过。

后台当前在请求前清空草稿，失败输入保留尚未实现；详情请求缺少移动端的加载序号保护，实时刷新忙碌时会忽略后续通知，也未增加 trailing 刷新。SSE JSON 解析和业务操作异常反馈仍需加强。后台卸载会关闭 EventSource，移动端连接所有者策略另有待办。两端不能统一宣称已具备相同可靠性。

当前 sender/reader 由客户端提交，Mock 无真实身份与租户隔离，结束会话及接入也不是生产坐席权限模型。原客服 WebSocket 与当前 HTTP/SSE 演示分别说明。

### 消息去重与消费队列

入口：[实时待办页](../src/views/demo/realtime/index.vue)。本地按钮生成事件，根据 ID 去重，有效事件顺序消费后更新分类计数；提示音使用单独队列，避免直接并发播放。

连接恢复用定时器模拟，虽然有退避延迟公式，每次模拟会在定时回调后成功；没有真实 WebSocket 建连、心跳、断线补偿及连续失败验收。去重集合只在当前页面生命周期内存在，不宣称跨刷新去重或生产消息可靠性。

这一部分可围绕客户端事件处理、队列与资源释放讨论设计取舍，示例效果以当前可复现结果为依据。
